# 论文信源与筛选规则

本文件定义抓取与筛选的通用方法论，**与具体业务线无关**。检索对象（查哪些方向、关键词、arxiv 分类、相关性阈值、上限篇数）全部由 profile 定义。

## 一、信源

两路并行，互补去重：

1. **arXiv 每日 RSS**：按 profile 的 `arxiv_categories` 逐分类抓取当期新论文，在本地用 profile 的 `research_directions[].keywords` 做关键词初筛。覆盖面广，含未被社区关注的新工作。
2. **HuggingFace Daily Papers**：社区投票筛出的每日热门论文，已带热度信号。按发布日期抓取覆盖窗口内每天的论文，按 upvotes 排序。

两路结果按 `paper_id`（arXiv ID）去重合并。同一篇以 arXiv 为准补全元数据（作者、发布日期、PDF 链接）。

## 二、覆盖窗口（周报口径）

- **运行节奏**：建议每周三由人工触发一次（本 Skill 手动触发，不做无人值守定时，原因见 SKILL.md 第 2 节）。
- **窗口**：上周三 00:00:00 至本周二 23:59:59，即运行日往前推的完整 7 天。窗口结束日取最近一个已过完的周二，建议周三运行，恰好覆盖完整一周。
- 窗口由 `scripts/resolve_week.py` 计算，勿手填日期。

## 三、筛选原则

1. **相关性优先，宁缺毋滥**。上限由 profile 的 `max_papers` 定义（当前 10 篇），**不足不强凑**。一周只有 3 篇真正相关，就只出 3 篇。
2. **相关性锚点**见 profile 的 `relevance_anchor`：判断标准是“方法 / 结论 / 问题建模能否迁移到业务线的实际问题”，**技术领域不限**。一篇 NLP、RL、甚至推荐系统的论文，只要方法可迁移，就相关；一篇顶会但与业务线无迁移路径的工作，不相关。
3. **相关性评分 1–5 分**，低于 profile 的 `relevance_threshold`（当前 3 分）不入选。评分依据是迁移价值的强弱与直接程度，不是论文本身的学术质量。
4. `out_of_scope`（见 profile）列出的方向直接排除。

## 四、评分与入选的证据要求

- 每篇入选论文必须能说清“为什么相关”——即它属于 profile 的哪个 `research_direction`、迁移路径是什么。说不清迁移路径的，不该给到入选分。
- 抓取到但未入选的论文无需在周报体现（周报只呈现真实入选内容，不写“本周还检索到 N 篇不相关”这类负向流水）。

## 五、事实与推断分离

- 论文的结论、数字、方法是**事实**，按原文陈述。
- 论文对业务线的价值是**推断**，是本 skill 的分析增量，必须与事实分开，不得混为一谈，不得让读者误以为论文在业务线场景做过验证。
